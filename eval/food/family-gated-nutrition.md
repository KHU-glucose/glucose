# 음식 계열 우선 → 동일 계열 내 영양 참고값 비교

2026-10-08 사용자 합의: 음식 종류가 다른데 영양 수치만 비슷하다는 이유로 정답 처리하지 않는다.
떡볶이→치즈떡볶이처럼 같은 음식 계열일 때만 영양 차이를 비교한다.
운영 음식 인식 API·프롬프트·모델·이미지 설정과 기존 이름 점수는 바꾸지 않았다.

## 평가 순서와 지표

1. **음식명 정확도:** 기존 정답 이름·사전 동의어 채점을 그대로 유지한다.
2. **큰 분류 정확도:** 고정 명칭 표의 계열을 일대일로 맞춘 수 / 명칭 표에 등록된 정답 음식 수.
   실패·누락·다른 계열·미등록 예측은 분모에 남고 정답이 아니다. 미등록 정답은 채점 제외하되
   전체 작성된 정답 대비 명칭 표 커버리지를 공개한다. 이 지표는 recall이며 전체 음식 precision은 아니다.
3. **동일 계열 내 영양 비교:** 계열이 맞고 대응이 명확하며 두 음식의 검수된 자료가 있을 때만
   100g당 탄수화물·당류의 절대 차이와 부호 있는 차이(예측−정답)를 계산한다.
   두 성분 중 하나라도 값이 없으면 보류한다. 누락값을 0으로 간주하지 않는다.

이 세 단계는 두 큰 축(음식 인식 / 영양 참고값 비교)을 세분한 것이며 점수를 평균하지 않는다.
기존 `management_group` 채점은 호환성을 위해 남기고 새 음식 계열 점수와 구분한다.
같은 계열이라고 영양적으로 정답 처리하지 않는다. 임상 허용 오차나 임의의 유사도 %를 만들지 않았다.
현재 출력은 g/100g 오차이며 유사도 PASS 목표가 없다.

| 정답 → 예측 | 계열 판정 | 영양 비교 |
| --- | --- | --- |
| 떡볶이 → 치즈떡볶이 | 같은 계열 | 두 음식의 자료 확보 후 비교. 현재는 자료 부족 |
| 김밥 → 참치김밥 | 같은 계열 | 두 음식의 자료 확보 후 비교. 현재는 자료 부족 |
| 계란찜 → 죽 | 다른 계열 | 수치가 같더라도 비교 금지 |
| 갈치구이 → 생선구이 | 일반 구이 계열 | 어종 미확정 이름의 자료가 없으므로 보류 |
| 갈치구이 → 고등어구이 | 일반 구이 계열 | 기존 출처로 100g 참고값 차이 계산 가능 |

계열 판정은 실제 사진이 아니라 **기존 정답 음식명의 분류**다. 원본 라벨 자체가 잘못되거나
추가 치즈 유무를 검수하지 않았다면 이 평가가 이를 해결하지 않는다. 먼저 사진을 확인해야 한다.

## 초기 명칭 표와 자료 범위

원본은 `ml-service/food_family_policy.json` (`food-family-v1`)이다.

- 떡볶이: 떡볶이, 치즈떡볶이
- 김밥: 김밥, 참치김밥
- 계란찜: 계란찜
- 죽: 죽, 야채죽, 채소죽
- 일반 생선구이: 갈치구이, 고등어구이, 연어구이, 생선구이

**전체 음식 분류를 완성한 표가 아니다.** 이름은 NFKC·공백·대소문자 정규화 후 정확하게 연결한다.
부분 문자열, aliases, category_hint, tags, LLM의 임의 판단으로 계열을 추가하지 않는다.
‘밥 포함 정식’, ‘달콤한 양념’, ‘튀김옷’ 등을 등록되지 않은 일반 구이에 자동 포함하지 않는다.

영양 자료는 기존 `food_management_policy.json`에서 출처를 확인했던 갈치구이·고등어구이
두 참고값만 재사용했다. 새 음식의 평균 영양 수치를 LLM에게 추측시키지 않았다.
자료마다 출처 URL·제목·페이지 또는 식품 ID, 100g 기준, 제한과 `review_status=VERIFIED`가 필요하다.
이 필드는 검수 기록용 선언이며 자동으로 출처의 진실성을 증명하지 않는다. 실제 담당자가 검수한다.
모든 음식에 영양 자료가 있을 필요는 없지만 없는 자료는 비교 보류로 남는다.

LLM으로 자료를 보완한다면 공식 DB에서 후보를 찾아 연결하는 **초안**만 만들게 한다.
이름·조리법·원료·가식부와 단위를 사람이 확인한 자료만 새 정책 버전에 넣는다.
서로 다른 여러 레시피를 무작정 평균내거나, 이름이 포괄적인 ‘죽’·‘생선구이’에 특정 음식 수치를 붙이지 않는다.

## 여러 음식과 커버리지

같은 계열 안에서도 음식명이 정확히 같은 쌍부터 일대일로 대응한다. 이후 남은 정답과 예측이
각각 하나인 경우만 수치 비교한다. 대응이 여러 개 가능하면 영양값이 가장 가까운 것을 골라
유리하게 채점하지 않고 `AMBIGUOUS_PAIRING`으로 보류한다. 한 예측은 두 정답을 맞힐 수 없다.

보고서는 다음을 구분한다.

- 전체 작성된 정답 중 명칭 표 등록 수와 계열 일치 수
- 계열 일치 중 영양 비교 완료 수 / 자료 부족 / 값 누락 / 대응 불명확 수
- 비교 완료 / 계열 일치, 비교 완료 / 등록 정답, 비교 완료 / 전체 작성 정답
- 비교한 쌍의 평균 절대 차이와 평균 부호 차이
- **음식명이 실제로 달라진 쌍만의** 비교 수와 오차 (정확한 이름 쌍의 0 오차와 별도)

영양 참고값이 비슷해도 실제 혈당 반응을 검증한 것이 아니다. 실제 섭취량·조리법·개인 반응을
확인한 값이 아니며 영양 수치를 운영 API 응답에 넣지 않는다.

## 오프라인 실행

`eval_food_family.py`는 기존 raw 보고서를 다시 읽을 뿐 이미지 전송이나 유료 API 호출을 하지 않는다.
원본 정답·예측·보고서를 바꾸지 않고, 새 출력 경로만 허용한다. 같은 사진이 중복된 보고서는 거부한다.
출력은 원본 경로·음식명 등을 포함하므로 Git 제외된 `food_testing/` 또는 `eval/food/reports/` 안에 둔다.
JSON의 `accuracy_summary.family_gated_nutrition`에 정책 버전·해시·전체 스냅샷·음식별 대응이 남는다.

```powershell
python ml-service/eval_food_family.py `
  --report food_testing/benchmark-v3-primary-20261008-v2/v3-execution-01/raw-pilot.json `
  --report food_testing/benchmark-v3-primary-20261008-v2/v3-execution-01/raw-development.json `
  --report food_testing/benchmark-v3-primary-20261008-v2/v3-execution-01/raw-reserved.json `
  --output food_testing/benchmark-v3-primary-20261008-v2/family-gated-review-next.json
```

커스텀 표는 `--family-policy 새정책.json`으로 명시한다. 모델·프롬프트·사진·라벨 조건이 같은
원본 보고서끼리만 합쳐 해석한다. 정상 평가 실행의 요약에도 기본 계열 표와 수치 비교가 추가된다.
기존 음식명/관리 그룹 지표와 완료 목표는 유지된다.

## 현재 100장 결과를 이용한 동작 확인

로컬 `family-gated-review-20261008-v1.json`을 별도로 생성했다. 추가 API 호출은 0회.
세 raw 보고서·기존 summary·두 라벨 파일, 총 6개 원본의 SHA256이 전후 동일함을 확인했다.
오프라인 자동 테스트는 ML 100개와 평가 도구 13개, 총 113개가 통과했다.

- 기존 음식명: **71/100 그대로**.
- 초기 명칭 표 등록: **10/100개 정답**. 이 제한된 범위에서 계열 일치 **7/10**.
- 계열 일치 7쌍 중 영양 비교 가능: **1쌍**. 나머지는 자료 부족.
- 그 1쌍은 음식명이 같은 갈치구이 쌍이다. **음식명이 다른 쌍의 영양 비교는 아직 0쌍 / 미측정**.

7/10은 전체 음식 계열 정확도가 아니다. 1쌍의 0g 차이는 이름 변경의 영양적 타당성을 검증하지 않는다.
현재 기준은 예측을 본 뒤 추가한 **사후 진단 기준**이다. 프롬프트 성능 향상이나 80% 달성 근거로 쓰지 않는다.
