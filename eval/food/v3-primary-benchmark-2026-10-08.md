# v3 대표 음식 인식 예비평가 준비 기록

## 현재 상태

운영 기본 프롬프트는 `examples-v3`. v4, v5, v6는 실험 후보이며 기본값을 바꾸지 않았다.
모델 `gpt-6-luna`, 이미지 detail=low, 최대 변 768px, 출력 1200토큰, 재시도 정책을 유지한다.

이전 v3는 동일 개발용 10장을 2회 실행해 대표 음식명 12/20 (60%)을 맞췄다.
이는 서로 다른 사진 20장의 성능이나 최종 정확도가 아니다. 새 사진의 기준선을 얻기 위해
v3부터 평가한다. v3가 가장 좋은 버전으로 입증되었다는 뜻은 아니다.

## 선정

`food_testing/benchmark-v3-primary-20261008-v2/`에 사진 경로·정답·출처를 고정했다.
사진은 기존 데이터 폴더에 그대로 두고 복사하거나 덮어쓰지 않는다.

- 한식 20종류 × 2장 = 40장. 폴더 분류 라벨 사용.
- Food-101 20종류 × 2장 = 40장. 원본 validation만 사용.
- Grocery 10개 상위 종류 × 2장 = 20장. 원본 test와 클래스 매핑 사용.
- 종류별 한 장은 개발용, 다른 한 장은 예약 검증용: 각각 50장.
- 이전 평가 보고서·기존 10장 정답에 등장한 이미지 SHA256 제외.
- 선정 100장 서로 다른 SHA256이며 Food-101 전체의 동일 바이트 중복 이미지도 제외.
- 유형을 미리 정한 목적 표본이다. 실제 앱 사용 빈도를 반영한 무작위 표본은 아니다.

원본 클래스→한국어 대응표와 허용 동의어는 AI 결과를 보기 전에 작성했다.
이는 팀원이 직접 검수한 새 정답이 아니라, 기존 데이터 분류 라벨의 대응표다.
완전한 사진별 정답으로 표시하지 않는다 (`annotation_complete=false`).

최초 준비 v1은 보존하고, API 실행 전에 v2를 만들었다. 선정 사진·분할은 동일하다.
Food-101 ramen에 한국식 인스턴트 라면도 들어 있어 라면 명칭을 허용하고,
컵케이크·도넛·키위 등의 명백한 하위 명칭을 제한된 동의어에 추가했다.
이는 데이터의 대표 클래스 평가 범위를 정한 것으로 혈당 관리용 영양 동등 그룹이 아니다.
모델 출력을 보고 정답을 변경한 작업은 아니다.

사전 시각 확인에서 77번 `fried_rice` 사진의 분류가 애매함을 기록했다.
AI가 정답을 바꾸거나 유리한 사진만 남기지 않도록 해당 사진을 그대로 포함하며,
실제 보고서에서 인간 정답 검수가 필요하다는 제한을 명시한다.

## 측정 범위

핵심 지표는 **사진의 원본 대표 음식 클래스가 예측 목록에 있는 비율**이다.
사전에 정한 한국어 명칭·허용 동의어의 완전 일치로 계산한다. API 실패도 분모에 넣는다.
동의어를 빼고 정확히 이름만 일치한 수, 출처별 점수, 성공 응답 수, 실패 코드,
모든 시도 처리 시간 중앙값도 별도로 기록한다.

원본 라벨은 보이는 음식 전체를 다루지 않아 raw 리포트의 precision/F1을 의미 있는
전체 음식 성능으로 해석하면 안 된다. 예비평가 요약에서는 이 수치를 제외한다.
개수, 분류 힌트, 혈당 관리 그룹, 비음식 거르기, 당류·탄수화물 추정도 평가하지 않는다.
완료 목표 85% 충족이나 프롬프트 개선이 입증되었다고 주장하지 않는다.

## 외부 전송 승인과 실제 실행

2026-10-08 실행 요청은 자동 안전 검토에서 거부되었다.
선정한 로컬 음식 사진 100장(사용자가 가져온 한국 음식 포함)을 외부 OpenAI API로
전송하고 API 비용이 발생한다는 데 대한 명시적인 사용자 승인을 요구했다.
이 거부된 명령은 시작되지 않았으며 그 시점에는 실제 API 호출·과금·성능 결과가 없었다.

이후 사용자가 선정한 100장을 OpenAI `gpt-6-luna`에 전송하고 사용료가 발생하는 평가를
진행해도 되는지에 대해 "어 해봐"로 승인했다. 승인 이후 실행을 완료했다.
첫 5장, 개발용 나머지 45장, 예약용 50장을 각각 1회씩 요청했다.
첫 5장 전부 유효 응답을 못 받으면 남은 95장은 중단한다. 서비스 재시도는 그대로다.
예측에 원본 클래스/정답을 보내지 않는다. 사진과 서비스의 기존 질문만 전달한다.

리포트와 정답은 `food_testing` 내부에 기록하여 GitHub에서 제외한다.
`run_primary_benchmark.py`는 실행 디렉터리가 있으면 멈추므로 무심코 유료 평가를
반복하거나 기존 결과를 덮어쓰지 않는다. 중단된 실행을 임의로 처음부터 재실행하지 않는다.

공식 표준 단가와 성공 응답 토큰량으로 비용을 추정할 수 있지만 재시도·실패·캐시 등은
기존 메타데이터만으로 완전히 계측하지 못한다. 추정치를 청구 금액이라고 표시하지 않는다.

참고: [OpenAI 공식 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices),
[사용 모델·표준 단가](https://developers.openai.com/api/docs/models/gpt-6-luna).

## 실행 결과

100장 실행 완료. 사전에 고정한 명칭·동의어 기준 대표 음식명 일치율은 71/100 (71%),
유효 응답은 99/100, 전체 시도 처리 시간 중앙값은 3.66초다.
사진 전체 음식·개수·혈당 관리 분류의 정확도로 해석하지 않는다.
