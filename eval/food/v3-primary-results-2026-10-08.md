# v3 대표 음식 인식 예비평가 결과 — 2026-10-08

## 결론

서로 다른 사진 100장으로 현재 기본 프롬프트 `examples-v3`의 기준선을 측정했다.
사전에 고정한 대표 음식명·허용 동의어 기준 **71/100 (71%)** 일치했다.
프롬프트, 모델, 이미지 설정과 채점 기준을 실행 중이나 결과를 본 뒤 바꾸지 않았다.

이는 사진의 대표 음식명 일치율이다. 앱 전체 음식 인식 정확도나 혈당 관리 정확도가 아니다.
다음 개선 전에 명칭의 구체성 차이와 실제 음식 혼동을 사람의 사진 검수로 구분해야 한다.

## 불일치의 해석 — 점수를 바꾸지 않은 사후 검수 후보

아래는 모델 결과와 원본 클래스 사이의 차이를 검토하기 위한 예시다.
사진별 정답을 사람이 확정한 오류 분류가 아니며, 자동 정답 인정이나 재채점에 사용하지 않았다.

| 검수 대상 | 원본 대표 이름 → 모델 출력 예시 | 확인할 점 |
| --- | --- | --- |
| 구체적인 이름 추가 | 김밥 → 참치김밥; 떡볶이 → 치즈떡볶이; 치즈케이크 → 블루베리 치즈케이크 | 원본 클래스와 구체성 수준이 다름. 추가 재료가 실제 보이는지도 검수 필요 |
| 서로 다른 음식의 항목 합치기 | 연어구이 → 연어구이와 밥 | 이름 일치뿐 아니라 항목 분리 문제 |
| 너무 넓은 이름 | 갈치구이 → 생선구이 | 생선 종류의 구체성을 놓쳤는지 확인 |
| 가까운 음식 사이 구분 | 삼계탕 → 닭곰탕; 까르보나라 → 크림파스타 | 명칭·재료 차이를 검수. 영양적으로 동등하다고 자동 인정하지 않음 |
| 다른 음식일 가능성 | 계란찜 → 죽/야채죽; 식혜 → 막걸리/죽; 키위 → 오렌지; 배 → 구아바 | 사진과 원본 라벨을 함께 확인한 뒤 실제 혼동 판단 |
| 원본 라벨 의심 | 볶음밥 → 밥 | 실행 전부터 분류가 애매하다고 표시한 77번. 점수에 그대로 포함 |

따라서 29건을 모두 실제 시각 인식 실패라고 단정할 수 없다.
반대로 세부 이름이 붙었다는 이유만으로 정답으로 인정하거나, 문자열 부분 일치만으로
점수를 올려서도 안 된다. 혈당 관리에서는 추가 재료·조리 방식 차이가 중요할 수 있다.

전체 음식의 precision/F1, 당류·탄수화물 양, 혈당 관리 그룹, 그래프 파싱은 평가하지 않았다.
원본 데이터는 대표 클래스만 알려주므로 사진의 추가 반찬·소스 등이 전부 정답으로
주석 처리되어 있지 않다 (`annotation_complete=false`).

과거 v3의 12/20 (60%)은 동일 사진 10장을 두 번 실행한 결과다. 이번 71%와 사진·기준이
달라서 11%p 개선이라고 해석하지 않는다. v3가 다른 프롬프트보다 우수하다는 증거도 아니다.
예약용 50장은 이번에 사용했으므로 이후에도 미사용 최종 검증셋이라고 부르지 않는다.

## 다음 실험의 우선순위

1. 팀원이 불일치 사진과 일부 일치 사진을 검수해 원본 라벨 오류, 명칭 범위 차이,
   실제 음식 혼동을 분리한다. 식사류의 대표 이름 수준과 간식류의 개수 기준도 정한다.
2. 별도 버전의 정답·동의어 정책을 검수 후 고정한다. 이번 v3 결과와 원본 정답은 보존한다.
   새 기준을 쓸 경우 비교할 모든 버전에 같은 기준을 적용하고 기준 변경을 기록한다.
3. 개발용 사진에서 한식 혼동, 근거 없는 재료 추측, 음식 항목 합치기를 대상으로
   프롬프트 후보를 만들고 v3와 동일 사진·설정·채점으로 비교한다.
4. 개선안을 정한 뒤 아직 보지 않은 새 사진과 전체 음식·개수·비음식 정답으로 최종 검증한다.
   혈당 관리 분류는 별도의 정답과 기준으로 평가한다.

이번 요청에서는 기준선 평가까지만 실행했다. 추가 유료 호출이나 프롬프트 변경은 하지 않았다.
