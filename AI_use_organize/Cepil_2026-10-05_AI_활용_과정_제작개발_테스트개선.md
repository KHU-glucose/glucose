## AI 활용을 통해 반영한 작업 내용

1. 기존 `jaehyun/`의 실제 Vision AI 프로토타입과 분리하여 `ml-service/`에 백엔드 연동용 Mock API를 구성했다.
2. 계약서에 맞춰 `GET /health`와 `POST /v1/food/recognize`를 구현했다.
3. 음식 인식 응답을 음식명·개수·단위·분류 힌트 중심으로 제한하고, 탄수화물·당류 등 영양소 수치를 제거했다.
4. `X-Internal-Token` 인증과 `X-Request-Id` 전달·응답 헤더 처리를 적용했다.
5. JPEG/PNG만 허용하고, 최대 8MB 제한과 Pillow 실제 이미지 디코딩 검증을 추가했다.
6. 입력 이미지를 메모리에서 긴 변 최대 768px로 축소하도록 구성했다.
7. 계약서 형식의 `400`, `401`, `502`, `504` 오류 응답 모델을 정의했다.
8. 이미지나 원본 AI 출력을 남기지 않고 요청 ID, 경로, 상태 코드, 지연 시간 등을 한 줄 JSON으로 기록하도록 구성했다.
9. `requirements.txt`와 Python 3.12 기반 Dockerfile을 정리했다.
10. 기능 브랜치에서 정확한 세 파일만 스테이징해 커밋·푸시하고 Pull Request를 생성했다.
11. WSL 2와 Docker Desktop을 설치한 뒤 이미지를 빌드하고 컨테이너에서 두 API를 실행 검증했다.

## 오류 분석 및 개선

### 1. FastAPI 시작 시 `Request` 이름 오류

발생한 문제:

```text
NameError: name 'Request' is not defined
```

AI 활용 내용과 참가자의 개선:

- traceback에서 `request: Request` 타입 선언 위치를 확인했다.
- FastAPI import 목록에 `Request`가 빠진 것이 원인임을 판단했다.
- 참가자가 import를 직접 수정하고 서버가 정상 시작되는지 재실행했다.

### 2. PowerShell 가상환경 활성화 차단

발생한 문제:

```text
PSSecurityException: 이 시스템에서 스크립트를 실행할 수 없습니다.
```

AI 활용 내용과 참가자의 개선:

- 시스템 전체 정책을 영구 변경하지 않고 현재 PowerShell 프로세스 범위에서만 실행 정책을 변경했다.
- `.venv`를 다시 활성화하고 이후 설치와 서버 실행을 진행했다.

### 3. Docker 명령 미인식과 WSL 설치 실패

발생한 문제:

```text
docker: 'docker' 용어가 인식되지 않습니다.
메모리 리소스가 부족하기 때문에 이 작업을 완료할 수 없습니다.
```

AI 활용 내용과 참가자의 개선:

- Docker가 미설치 상태임을 확인하고 WSL 2 기반 Docker Desktop 설치 순서를 선택했다.
- 최초 WSL 설치가 메모리 부족으로 중단되어 PC를 재부팅한 뒤 관리자 PowerShell에서 설치를 완료했다.
- Docker 설치 직후 기존 PowerShell이 갱신된 PATH를 읽지 못해 새 PowerShell을 열어 해결했다.
- `docker version`에서 Client와 Server 연결을 확인한 후 이미지 빌드와 컨테이너 테스트를 수행했다.

## 참가자 본인의 실질적 기여

- 계약서를 기준으로 실제 AI보다 Mock API를 먼저 제출하는 작업 순서를 선택했다.
- AI가 제시한 코드를 직접 입력·수정하고 각 단계마다 서버를 재실행했다.
- 정상 이미지와 여러 실패 입력을 직접 만들어 API와 Swagger에서 검증했다.
- 오류 화면과 traceback을 확인해 AI에게 전달하고 제안된 원인을 검토한 뒤 수정했다.
- 가상환경, 패키지, WSL, Docker Desktop을 직접 설치·설정했다.
- Docker 이미지 빌드, 컨테이너 실행, 두 API 호출, 컨테이너 종료를 직접 수행했다.
- Git에서 대상 파일만 선택적으로 스테이징하고 diff 검사, 커밋, 푸시, Pull Request 생성과 설명 수정을 직접 수행했다.
- 개인 문서와 `.env`를 스테이징 대상에서 제외했다.

AI는 계약 해석 정리, 구현 순서 설명, 코드 예시, 오류 분석과 명령 안내에 활용했으며, 범위 결정·코드 반영·실행·검증·Git 작업은 참가자가 직접 수행했다.
