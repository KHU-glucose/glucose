## AI 활용을 통해 반영한 개발 내용

1. FastAPI 프로젝트와 개발 서버를 구성하고 `GET /health` 상태 확인 API를 구현했다.
2. `POST /analyze-food` 엔드포인트에서 `UploadFile`로 음식 이미지를 입력받도록 구현했다.
3. 이미지 바이트를 Base64 Data URL로 변환해 OpenAI Responses API에 전달했다.
4. `AsyncOpenAI`와 `await`를 사용해 비동기 방식으로 API를 호출했다.
5. Pydantic과 Structured Outputs를 적용해 응답 형식을 고정된 JSON 구조로 만들었다.
6. 사진 속 여러 음식을 `foods` 배열에 각각 저장하도록 설계했다.
7. 음식별 예상 섭취량과 다음 네 가지 영양소를 반환하도록 구현했다.
   - 탄수화물
   - 단백질
   - 지방
   - 당류
8. GPT가 반환한 음식별 영양소를 Python의 `sum()`으로 다시 계산해 전체 합계의 일관성을 확보했다.
9. JPEG, PNG, WEBP만 허용하고 파일 크기를 10MB로 제한했다.
10. OpenAI API 인증, 사용량 제한, 서버 혼잡, 시간 초과, 네트워크, 잘못된 요청, JSON 파싱 오류를 구분해 HTTP 오류로 반환하도록 예외 처리를 추가했다.
11. Swagger에서 정상 음식 이미지, 음식이 아닌 이미지, 이미지가 아닌 파일을 직접 업로드해 결과를 검증했다.
12. 팀원이 같은 기능을 실행할 수 있도록 `requirements.txt`, `.env.example`, README를 정리하고 GitHub에 공유했다.

## 오류 분석 및 개선 사례

### 발생한 오류

Structured Outputs에 영양소 항목을 추가한 후 다음 오류가 발생했다.

```text
pydantic_core.ValidationError
Invalid JSON: EOF while parsing a string
```

### AI를 활용한 원인 분석

Swagger의 `500 Internal Server Error` 화면만으로 판단하지 않고, PowerShell traceback의 마지막 오류를 확인했다. JSON이 `estimated_protein_g` 필드 근처에서 끝난 사실을 근거로 출력 토큰 제한 때문에 응답이 중간에 잘린 것으로 분석했다.

### 반영한 개선

```python
# 변경 전
max_output_tokens=500

# 변경 후
max_output_tokens=2000
```

수정 후 여러 음식과 영양소 4종이 포함된 JSON 응답이 정상적으로 완성되는 것을 확인했다.
